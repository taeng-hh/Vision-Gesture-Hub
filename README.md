# Vision Gesture Hub

> 컴퓨터 비전 기반 멀티모드 손동작 인식 플랫폼 (Windows prototype)

웹캠으로 **한국수어 단어·문장을 번역**하고, 수어로 조작하는 **수화 갤러그** 게임으로 바로 넘어갈 수 있는 프로젝트입니다.

```powershell
python main.py
```

이 명령 하나로 수어 번역 화면이 열립니다. 단어 23개·문장 7개(30클래스)를 인식하고, 단어는 규칙에 따라 문장으로 조합합니다. 키포인트 GRU가 먼저 판정하고, 애매할 때만 RGB CNN이 같은 후보인지 확인합니다([인식 방식](#수어-인식-방식-키포인트-주판정--cnn-보조)).

- `Space`로 수어 입력을 시작하고, 동작을 마치면 다시 `Space`로 완료합니다.
- **녹화하지 않을 때 V 손 모양(검지·중지)을 1.2초 유지하면 수화 갤러그가 열립니다.** 게임에서 `Q`/`Esc`를 누르면 번역 화면으로 돌아옵니다.
- 녹화 중에는 게임 전환이 꺼집니다. 녹화 중에 V를 하고 있었다면 손을 풀었다가 다시 유지해야 합니다.

처음 설치하는 팀원은 **[팀원용 설치·자료 배치·실행 안내](docs/ksl_team_guide.md)**도 확인하세요. 학습된 모델은 저장소에 포함되어 있으며 학습 데이터는 포함하지 않습니다.

## 현재 구현 상태

| 항목 | 상태 |
|---|---|
| 한국수어 단어·문장 인식 (기본 화면) | 키포인트 GRU + CNN 보조 구현 / 웹캠 정확도 미측정 |
| V 손 모양 → 수화 갤러그 → 복귀 | 구현 |
| 수화 갤러그 (수어로 조작) | 구현 |
| 모드 선택 허브 (`--hub`) | 구현 (이전 메뉴) |
| 발표 제어: 엄지 올림/내림으로 슬라이드 변경 | 허브 안에서 기초 프로토타입 |
| PC 제어: 커서·클릭·확대/축소·Alt+Tab (`modes/pc_control.py`) | 코드만 있음 · 실행 경로 연결 여부는 팀 결정 대기 |
| 메모장·계산기 실행 허용 목록 | 함수 제공 / 제스처 연결은 미구현 |
| 사용자 정의 제스처 모델 | 미구현 |

## 요구 환경

- Windows 10/11, 웹캠, Python **3.11** 권장
- CPU로 시작 가능. 높은 FPS가 필수인 경우 측정 후 최적화
- PyAutoGUI는 일반적으로 **주 모니터**를 제어함. TV HDMI 시 복제 모드/주 모니터 설정을 확인

## 설치 (Windows PowerShell)

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
python scripts/setup_assets.py
python main.py
```

`requirements.txt` 하나에 실행에 필요한 패키지(MediaPipe, OpenCV, PyTorch·torchvision, Pillow)가 모두 들어 있습니다. OpenCV는 `opencv-contrib-python`만 사용합니다. MediaPipe가 이 패키지에 의존하므로 `opencv-python`을 따로 설치하면 `cv2`가 꼬입니다. 예전 가상환경에 `opencv-python`이 있다면 `pip uninstall opencv-python` 후 다시 설치하세요.

`scripts/setup_assets.py`는 MediaPipe 공식 손·자세·제스처 모델과 MobileNetV3 기본 가중치(약 33MB)를 내려받고 SHA256을 검증합니다. 수어용 키포인트 GRU(`models/ksl30_robust_v2`)와 RGB 3-시드 앙상블(`models/rgb_ksl30`)은 저장소에 포함되어 있습니다. 인터넷이 필요한 단계는 이 다운로드뿐입니다. 환경에 따라 PowerShell 실행 정책 때문에 가상환경 활성화가 차단될 수 있습니다. 그 경우 `.venv\Scripts\python.exe -m pip install -r requirements.txt` 와 `.venv\Scripts\python.exe main.py`처럼 직접 실행할 수 있습니다.

카메라가 열리지 않으면 `python main.py --camera 1`을 시도하세요.

### 실행 옵션

| 명령 | 화면 |
|---|---|
| `python main.py` | 수어 번역 화면 (기본, 키포인트 + CNN 보조) |
| `python main.py --camera 1` | 다른 카메라 사용 |
| `python main.py --no-game` | V 손 모양 게임 전환 끄기 |
| `python main.py --mode keypoint` | 키포인트 단독 판정으로 시작 (`rgb`, `fusion`도 가능) |
| `python main.py --diagnose` | 카메라 없이 모델 로드만 확인하고 JSON 출력 |
| `python main.py --legacy-ksl` | 이전 키포인트 GRU 단독 번역 화면 |
| `python main.py --runner` | 수화 갤러그 바로 실행 |
| `python main.py --hub` | 이전 모드 선택 메뉴 |

## 실행 키

### 수어 번역 화면 (기본)

| 키 / 동작 | 기능 |
|---|---|
| `Space` | 수어 입력 시작 / 완료 (완료 후 분석) |
| V 손 모양 1.2초 유지 | 수화 갤러그 열기 (녹화 중에는 꺼짐) |
| `1` / `2` / `3` | 키포인트 단독 / 영상(RGB) 진단 / 키포인트 + CNN 보조(기본) |
| `C` | 초기화 |
| `D` | 디버그 패널 켜기/끄기 (모델별 점수, 판정 기준, RGB 입력 ROI) |
| `Backspace` | 마지막 단어 삭제 |
| `Q` 또는 `Esc` | 종료 |

번역 화면과 게임은 `Sign Translator` 창 하나를 같이 씁니다(1280×860). 화면 미리보기는 [docs/ui/](docs/ui/)에 있고, `python scripts/render_ui_preview.py`로 다시 만들 수 있습니다.

`1`/`2`/`3`으로 모드를 바꾸면 직전 동작을 다른 모드로 다시 판정해 비교합니다. 아직 계산하지 않은 모델은 그때 추가로 분석합니다.

### 모드 선택 허브 (`--hub`)

| 키 | 동작 |
|---|---|
| `0` | 대기 화면 |
| `1` | 손 추적 표시만 (번역은 기본 화면에서 실행) |
| `2` | 수화 갤러그 실행 (`Q`/`Esc`로 허브 복귀) |
| `3` | 발표 제어 모드 |
| `E` | 발표 모드에서 실제 OS 키 입력 ON/OFF |
| `Q` 또는 `ESC` | 종료 |

**기본적으로 OS 입력은 비활성화**입니다. 모드 선택 후 미리보기 창에서 `E`를 눌러야 실제 키보드 동작이 발생합니다. 다른 모드로 전환할 때는 다시 OFF로 돌아갑니다.

### PC 제어 기능 (`modes/pc_control.py`, 현재 실행 경로에 연결되지 않음)

아래 기능은 코드로만 존재하며, 어느 실행 경로에 연결할지 팀에서 결정한 뒤 연결합니다.

- 화면 전체 확대·축소(Windows 돋보기): 엄지를 올린 자세(`Thumb_Up`)를 0.5초 유지하면 확대, 엄지를 내린 자세(`Thumb_Down`)를 유지하면 축소합니다. 유지하는 동안 0.6초 간격으로 반복합니다. 신뢰도 0.7 이상에서만 동작하며 자세 변경이나 인식 끊김 시 유지 시간을 다시 측정합니다.
- 확대·축소 중에는 커서와 클릭을 멈춥니다. 창 선택 중에는 확대·축소를 실행하지 않습니다. Windows 돋보기 종료는 `Win+Esc`입니다. 웹페이지 배율 조절과는 별개이며, 조작할 화면을 먼저 활성화하세요.

- OS 제어를 켠 상태에서 손바닥을 펼치고, 사용자 기준 오른쪽에서 왼쪽으로 밀면 `Alt+Tab` 창 선택 화면이 열립니다. 반복해서 밀 때마다 다음 후보로 이동합니다. 후보는 브라우저를 포함해 Windows의 Alt+Tab에 표시되는 창입니다.
- 미리보기 오른쪽 영역에서 시작해 0.8초 이내에 화면 너비의 약 22% 이상 수평 이동하세요. 손바닥을 펼친 동안에는 커서와 클릭이 멈춥니다.
- 손을 편 채 오른쪽으로 되돌린 후 다시 왼쪽으로 미세요. 스와이프 사이에는 최소 0.8초 간격이 필요합니다. 마지막 스와이프 후 2.5초 동안 추가 스와이프가 없으면 선택한 창으로 전환됩니다. 선택 중에는 커서와 클릭이 멈추며, 모드 전환·제어 해제·종료 시 Alt 키를 해제합니다.
- 창 선택 중 주먹을 0.3초 유지하면 현재 선택된 창으로 즉시 전환합니다. 주먹 인식 신뢰도는 0.7 이상이어야 하며, 손 인식이 끊기거나 자세가 바뀌면 유지 시간을 다시 측정합니다.

- 검지 끝(랜드마크 8)으로 커서를 이동합니다.
- 엄지와 중지를 약 0.08초 이상 붙이면 왼쪽 마우스 버튼을 누르고, 벌리면 놓습니다. 짧게 붙였다 떼면 클릭입니다.
- 붙인 채 검지를 움직이면 드래그합니다. 손 인식이 끊기거나 모드 전환, 제어 해제, 메뉴 버튼 선택, 프로그램 종료 시 버튼을 자동으로 놓습니다.
- 먼저 엄지와 중지를 벌려 `READY` 상태로 만든 뒤 붙이세요. 다시 클릭하려면 두 손가락을 다시 벌려야 합니다.
- OpenCV 카메라를 좌우 반전하여 거울식으로 표시합니다.
- 데스크톱 아이콘 실행은 환경에 따라 **더블클릭**이 필요하므로, 초기 버전은 단일 클릭만 제공합니다. 앱 실행은 향후 선택/더블클릭 동작 추가가 필요합니다.
- `modes/windows_app_launcher.py`에는 메모장·계산기 실행의 **허용 목록** 함수가 들어 있지만, 오실행 방지를 위해 아직 제스처에 연결하지 않았습니다.

### 발표 제어 모드

- `Thumb_Up` 8프레임 유지 → `Right` 키 1회
- `Thumb_Down` 8프레임 유지 → `Left` 키 1회
- 다른 모양/손을 치우는 중립 상태가 있어야 다음 명령을 실행합니다.
- 미리보기 창에 초점이 남아 있으면 슬라이드가 전환되지 않을 수 있습니다. 단축키를 받을 발표 프로그램을 활성화하세요.

## 폴더 역할

```text
fusion/     기본 수어 번역 화면: 키포인트 주판정 + CNN 보조, V 손 모양 게임 전환
ksl/        키포인트 GRU 데이터 형식·학습·추론 (Recognizer)
core/       카메라 인식 결과, 좌표 계산, 수어 입력 세션, 모드 상태 및 제스처 안정화

training/   데이터 수집 및 앞으로 추가할 모델 학습 코드
models/     ksl30_robust_v2(키포인트 GRU), rgb_ksl30(RGB 앙상블) 포함 / MediaPipe 모델은 setup_assets.py로 다운로드
data/       촬영/랜드마크 데이터 (gitignore)
scripts/    설치 보조 도구
sessions/   (아직 없음) 나중에 익명화된 실험 로그 모듈
screenshots (아직 없음) UI/시연 이미지 필요 시 별도 추가
```

## 안전·개인정보

- 운영 중 PyAutoGUI의 **화면 모서리 이동 fail-safe**를 유지합니다. `Q` 종료는 미리보기 창에 키보드 초점이 있을 때 동작합니다.
- 카메라 영상은 기본적으로 저장하지 않습니다. 데이터 수집은 사용자가 명시적으로 시작해야 합니다.
- 동의받지 않은 학생·교사 영상/랜드마크를 수집·업로드하지 마세요.
- 화면 바로 앞의 실제 터치를 탐지하려면 좌표 보정 및 깊이 감지 기술이 추가로 필요합니다.

## 23단어·7문장 키포인트 학습

팀 최종 목록은 `config/ksl_classes.json`에 정의되어 있습니다. 키포인트 준비,
GRU 학습, 촬영 그룹 분리 평가, 예측 이벤트와 영상 담당자용 공통 데이터 계약은
[학습 안내](docs/ksl_training.md)를 확인하세요.

```powershell
.venv\Scripts\python.exe -m pip install -r requirements-training.txt
.venv\Scripts\python.exe -m ksl.prepare --source "다운로드 폴더" --output data/ksl30
```

문장 자료가 없으면 전체 30클래스 학습은 진행되지 않습니다. 단일 촬영 그룹의
부분 실행 점검은 `--smoke-only --allow-partial`을 명시해야 하며 정확도 평가가 아닙니다.
배포용 30클래스 가중치와 클래스 정보는 저장소에 포함합니다. 학습 데이터는 별도 전달합니다. 키포인트 GRU 단독 웹캠 화면은 `main.py --legacy-ksl`로 실행합니다(기본 화면도 같은 GRU를 주판정으로 사용).
영상에서 같은 형식으로 좌표를 추출하는 기능은 별도 구현 대상이며, 게임에는 액션 메타데이터만 제공합니다.

**처음 실행하는 팀원은 [팀원용 안내](docs/ksl_team_guide.md)를 먼저 확인하세요.**

## 수화 갤러그

`python main.py`로 실행하면 수어 번역 화면이 먼저 열립니다.
녹화하지 않을 때 V 손 모양(검지·중지)을 1.2초 유지하면 게임이 열립니다.
게임에서 Q/Esc 또는 창 닫기로 나가면 수어 번역 화면으로 돌아옵니다.
수화 녹화 중에는 게임 전환이 비활성화되며, V 손 모양을 풀어야 다시 전환할 수 있습니다.

허브(`--hub`)의 2번 카드도 이 `SIGN GALAGA` 우주 슈팅 게임을 엽니다.
`python main.py --runner`로 바로 실행할 수도 있습니다.
직접 실행 시 `--camera`, `--model`, `--pose-model` 옵션을 사용할 수 있습니다.

- Space로 수화를 녹화하고 동작을 마친 뒤 Space로 완료합니다. 녹화 중에는 게임이 정지합니다.
- 시작/달리다: 출격, 왼쪽/오른쪽/위/아래: 우주선 방향 이동, 빠르다: 5초 연사.
- 탄환은 자동 발사됩니다. 적 편대와 급강하하는 적을 격추하고 적 탄환을 피하세요.
- 편대 적은 100점, 급강하 중인 적은 200점입니다. 모두 격추하면 다음 스테이지로 진행합니다.
- 목숨은 3개이며 피격 후 2초간 무적입니다. 스테이지가 오를수록 적 공격이 빨라집니다.
- P: 일시정지, R: 초기화, Q/Esc: 메뉴로 복귀. 시작 수화 또는 Enter로 다시 시작합니다.
- 테스트 키: Enter 출격, W/A/S/D 상하좌우 이동, F 연사.
- 기본 모델: models/ksl30_robust_v2, 자세 모델: models/pose_landmarker_lite.task.
- 손/어깨 추적이 없으면 게임이 멈춥니다. 상반신이 카메라에 보이게 해 주세요.

## 수어 인식 방식 (키포인트 주판정 + CNN 보조)

이영민님이 만든 assisted 엔진(`fusion/`)을 기본 화면으로 사용합니다. 판정 규칙은 [docs/ksl_assisted/ASSISTED_POLICY.md](docs/ksl_assisted/ASSISTED_POLICY.md)에 정리되어 있습니다.

- 키포인트 GRU(`models/ksl30_robust_v2`, 최정원님 학습 모델) 판정이 기준(점수 0.75, 1·2위 차이 0.15)을 넘으면 CNN 없이 바로 출력합니다.
- 키포인트가 애매할 때만 RGB CNN(MobileNetV3 Small + GRU, 3개 시드 앙상블)을 실행합니다. 두 모델이 같은 후보를 가리킬 때만 키포인트 80%·CNN 20%로 다시 확인합니다.
- 후보가 다르거나 CNN이 실패하면 보류합니다. CNN만으로는 결과를 확정하지 않습니다.
- 촬영 중 얻은 손·상체 관절을 재사용해 입력이 끝난 뒤의 지연을 줄입니다. 추적이 부족하면 원본 프레임을 다시 분석합니다.
- 화면에 손·상체 스켈레톤, 모델별 후보, 분석 시간, RGB 입력 ROI를 표시합니다.
- 완료 후 분석하는 방식이며, 연속 수어를 자동으로 끊어 인식하는 기능은 아닙니다.

**확인한 범위와 한계**: AI Hub REAL09 검증에서 키포인트 단독은 22/30, RGB 단독은 30/30이었습니다. 이 수치는 웹캠 정확도가 아닙니다. 실제 사용자 웹캠에서는 RGB가 약하다는 피드백이 있어 보조 용도로만 씁니다. 새 보조 정책이 웹캠 정확도를 개선했는지는 아직 측정하지 않았습니다. 점수는 보정된 정답 확률이 아닙니다.

**모델 출처**: 키포인트 가중치는 이 저장소 커밋 `609e3cf`의 모델이며(REAL01 30개 동작을 증강한 750개 입력), 출처는 `models/ksl30_robust_v2/provenance.json`에 있습니다. RGB는 REAL01~08로 학습하고 REAL09로 검증해 고른 세 시드 앙상블입니다. REAL10은 이전 RGB 평가에 이미 사용했으므로 미사용 최종 테스트가 아닙니다. 상세 기록은 [docs/ksl_assisted/](docs/ksl_assisted/)에 있습니다.
